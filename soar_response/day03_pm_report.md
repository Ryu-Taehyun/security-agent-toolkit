## 5교시 · 기록을 보고 자동이 바꾼 것만 되돌리고, 되돌릴 수 없는 조치는 따로 표시하기

### 문제 5-1 · 기록을 보고 자동이 바꾼 것만 되돌리기

- (가) 실행한 출력 전체를 붙여 넣어 주세요. 그리고 단계 5 의 잠긴 계정과 차단한 IP 를 적어 주세요.
  - 쓸 내용: ① 출력 전체(코드 상자에 붙여 넣기) ② 단계 5 의 잠긴 계정 ③ 단계 5 의 차단한 IP
  - 답: 출력은 아래와 같습니다. 단계 5 의 잠긴 계정은 `['junho']`, 차단한 IP 는 `[]`(없음)입니다.

```
--- 단계 1: 4교시가 남긴 파일
잠긴 계정: ['junho', 'dami']
조치 기록: 5 건
차단한 IP: ['198.51.100.90']
--- 단계 2: INC-001 은 오탐으로 확인됨 — 되돌리기
INC-001 dami · 되돌리기 불가 · 세션 2개 → 세션 0개 · 되돌릴 수 없는 조치(세션 종료) — 사용자가 다시 로그인해야 함
INC-001 dami · 계정 해제 · 잠김 → 잠기지 않음 · 되돌리기: 퇴사한 계정의 서버 요청
--- 단계 3: INC-006 도 오탐으로 확인됨 — 되돌리기
INC-006 junho · 되돌리기 불가 · 세션 1개 → 세션 0개 · 되돌릴 수 없는 조치(세션 종료) — 사용자가 다시 로그인해야 함
--- 단계 4: INC-005 도 오탐으로 확인됨 — 되돌리기
INC-005 198.51.100.90 · IP 해제 · 차단됨 → 차단되지 않음 · 되돌리기: 경로 스캔 (120분 뒤 자동 해제)
--- 단계 5: 되돌린 뒤 상태
잠긴 계정: ['junho']
차단한 IP: []
```

- (나) 🔍 INC-006 의 `junho` 는 단계 3 에서 계정이 해제되지 않았고 단계 5 에도 잠겨 있습니다. 4교시 기록의 `before` 와 `after` 를 근거로 이유를 적고, `should_undo` 의 5 · 6번이 없었다면 어떤 일이 생겼을지 적어 주세요.
  - 쓸 내용: ① 4교시 기록에서 `junho` 의 `before` · `after` ② 해제되지 않은 이유 ③ 5 · 6번이 없을 때 생기는 일
  - 답: 4교시 기록에서 `junho` 의 계정 잠금은 `잠김 → 잠김` 입니다. `before` 와 `after` 가 같아 5 · 6번에서 `False` 가 되므로 되돌리지 않았고, 조치 전부터 잠겨 있던 계정이라 자동이 바꾼 것이 아니기 때문입니다. 5 · 6번이 없으면 `계정 잠금` 은 되돌릴 수 있는 조치 종류라서 `junho` 도 해제되어, 원래 잠겨 있어야 할 계정이 풀리는 사고가 납니다.

- (다) 🔍 단계 2 의 `되돌리기 불가` 줄이 나온 이유를 적어 주세요. 또 세션 종료를 기록에 남기지 않고 「모두 원래대로」라고만 보고하면 어떤 문제가 생길지 적어 주세요.
  - 쓸 내용: ① `되돌리기 불가` 줄이 나온 이유 ② 기록하지 않고 「모두 원래대로」라고 보고할 때의 문제
  - 답: `dami` 의 세션 종료는 `세션 2개 → 세션 0개` 로 바뀌었는데 `세션 종료` 는 해제로 되돌릴 수 있는 조치(`UNDOABLE_ACTIONS`)가 아니라서 되돌리지 못하고 따로 기록했습니다(사용자가 다시 로그인해야 함). 기록 없이 「모두 원래대로」라고만 보고하면 사실과 달라서, 세션이 끊긴 사용자가 있다는 걸 사람이 모르고 문의가 와도 원인을 찾지 못합니다.

## 6교시 · 알림 8건을 판단 → 조치로 처리하고, 기록을 요약해 확인 목록 만들기

### 문제 6-1 · 알림 8건을 처리하고 기록을 요약해 확인 목록 만들기

- (가) 실행한 출력 전체를 붙여 넣어 주세요. 그리고 단계 3 의 요약과 단계 4 의 건수를 적어 주세요.
  - 쓸 내용: ① 출력 전체(코드 상자에 붙여 넣기) ② 단계 3 의 요약 ③ 단계 4 의 건수
  - 답: 출력은 아래와 같습니다. 단계 3 의 요약은 `{'변경됨': 2, '변경 없음': 2, '확인 실패': 1}` 이고, 단계 4 는 4건(INC-003 · INC-010 · INC-005 · INC-008)입니다.

```
--- 단계 1: 알림 8건 처리
INC-001 dami -> 조치함 (조치 기록 2건)
INC-002 seoyeon -> 조치하지 않음 (조치 기록 0건)
INC-003 gaeun -> 승인 대기 (조치 기록 0건)
INC-004 jiwoo -> 오탐 종료 (조치 기록 0건)
INC-005 198.51.100.90 -> 조치 실패 (조치 기록 1건)
INC-008 192.0.2.41 -> 승인 대기 (조치 기록 1건)
INC-009 192.0.2.10 -> 조치하지 않음 (조치 기록 1건)
INC-010 gaeun -> 승인 대기 (조치 기록 0건)
--- 단계 2: 조치 기록
INC-001 dami · 계정 잠금 · 잠기지 않음 → 잠김 · 퇴사한 계정
INC-001 dami · 세션 종료 · 세션 2개 → 세션 0개 · 퇴사한 계정
INC-005 198.51.100.90 · IP 차단 · 차단되지 않음 → 차단되지 않음 (확인 실패) · 방화벽 연결 실패
INC-008 192.0.2.41 · IP 차단 · 변경 없음 → 변경 없음 · 여러 계정이 함께 쓰는 IP 라서 담당자 승인 필요
INC-009 192.0.2.10 · IP 차단 · 변경 없음 → 변경 없음 · 허용 목록 IP 라서 차단하지 않음
--- 단계 3: 근무 보고 요약
{'변경됨': 2, '변경 없음': 2, '확인 실패': 1}
잠긴 계정: ['junho', 'dami']
차단한 IP: []
--- 단계 4: 담당자 확인이 필요한 건
INC-003 gaeun : VIP 계정이라 담당자 승인이 필요함
INC-010 gaeun : VIP 계정이라 담당자 승인이 필요함
INC-005 198.51.100.90 : 조치 후 확인 실패 — 방화벽 연결 실패
INC-008 192.0.2.41 : 여러 계정이 함께 쓰는 IP 라서 담당자 승인 필요
```

- (나) 🔍 INC-005 는 `조치 실패` 로 나왔고 요약의 `확인 실패` 가 1 입니다. 단계 2 의 줄을 근거로 이유를 적고, 6번(`is_failure`, 확인 실패인지 구하는 함수)이 없다면 이 건이 근무 보고에서 어떻게 보일지 적어 주세요.
  - 쓸 내용: ① INC-005 가 `조치 실패` 인 이유(단계 2 의 줄) ② 6번이 없을 때 근무 보고에서 보이는 모습
  - 답: 단계 2 에 `INC-005 … 차단되지 않음 → 차단되지 않음 (확인 실패) · 방화벽 연결 실패` 로 남았습니다. 방화벽 연결이 끊겨 IP 가 실제로 차단되지 않았기 때문입니다. 6번이 없으면 `확인 실패` 를 못 알아보고 before 와 after 가 다르다고 보아 `변경됨` 으로 세어져, 차단 안 된 공격 IP 가 「조치함」처럼 보이고 사람 확인 목록에서도 빠집니다.

- (다) 🔍 INC-008 과 INC-009 는 모두 차단되지 않았습니다. INC-008 은 승인 대기이고 INC-009 는 조치하지 않음입니다. INC-003 과 INC-010 도 승인 대기입니다. INC-003 · INC-008 · INC-009 · INC-010 네 건이 왜 그렇게 나왔는지 단계 2 와 단계 4 의 줄을 근거로 적어 주세요. 또 이 네 건을 그대로 자동 처리했다면 누가 어떤 영향을 받았을지 적어 주세요.
  - 쓸 내용: ① INC-008 · INC-009 가 차단되지 않은 이유 ② INC-003 · INC-010 이 승인 대기인 이유 ③ 그대로 자동 처리했을 때의 영향
  - 답: ① INC-008 은 `ip_users.json` 에서 `junho` 와 `hana` 가 함께 쓰는 IP 라 `담당자 승인 필요` 로 승인 대기이고, INC-009 는 허용 목록의 점검 서버라 `허용 목록 IP 라서 차단하지 않음` 으로 조치하지 않았습니다. ② INC-003 · INC-010 은 단계 4 에 `VIP 계정이라 담당자 승인이 필요함` 으로 나온 `gaeun` 이라 자동으로 잠그지 않고 승인 대기로 두었습니다. ③ 자동 처리했다면 INC-008 은 `junho` · `hana` 두 사람이 함께 접속을 못 하고, INC-009 는 회사 점검 서버가 막히며, INC-003 · INC-010 은 계정 관리자 `gaeun`(INC-010 은 인사 입력 실수인데도)이 잠겨 업무가 중단됩니다.
