## 5교시 · 설정 파일이 고장 나도 거부하기

### 문제 5-1 · 설정 파일을 안전하게 읽는 함수 `load_json` 만들고, 고장 두 가지로 시험하기

- (가) 실행한 출력 전체를 붙여 넣고, 경고 두 줄이 각각 어떤 오류 때문에 나왔는지 적어 주세요.
  - 쓸 내용: ① 출력 전체 ② 경고 두 줄이 각각 어떤 오류 때문에 나왔는지
  - 답:등록된 사용자가 없고 json 문자열이 깨졌기 때문에

```
[경고] 설정 파일 없음 : config/users.json
config/users.json -> 사용자 0 명, 등록된 사용자가 없다
[경고] 설정 파일 없음 : config/users_typo.json
config/users_typo.json -> 사용자 0 명, 등록된 사용자가 없다
[경고] 설정 파일 없음 : config/users_broken.json
config/users_broken.json -> 사용자 0 명, 등록된 사용자가 없다
```

- (나) 🔍 실패했을 때 프로그램을 멈추지 않고 빈 설정을 리턴하는 것이, 오류로 멈추는 것보다 왜 안전한가요? 「멈춘 뒤 현장에서 생기는 일」을 넣어 적어 주세요.
  - 쓸 내용: ① 빈 설정을 리턴하는 이유 ② 멈춘 뒤 현장에서 생기는 일
  - 답:(가)에서는 세 경로 모두 「설정 파일 없음」 경고가 났지만, 프로그램이 중단되지 않고 각 경로에 대해 사용자 0명을 출력했다. 파일을 읽지 못했을 때 빈 설정을 반환하면, 이 설정으로 판정할 경우 모든 요청을 거부하여 기본 거부를 유지할 수 있다. 반대로 판정 프로그램이 오류로 멈추면 현장에서 급한 정산 업무를 처리하려고 판정 기능을 끄거나 건너뛰어 모든 요청을 허용할 위험이 있다. 따라서 오류를 알리면서 빈 설정으로 거부하는 것이 권한 없는 접근을 막는 데 더 안전하다.

- (다) 🔍 설정 파일이 깨져서 모두 거부되면 정산 업무가 멈춥니다. 운영자가 이 상황을 빨리 알고 복구하려면 판정 프로그램에 무엇을 더하겠습니까? 두 가지 이상 적고, 그중 가장 먼저 할 것을 고른 이유를 적어 주세요.
  - 쓸 내용: ① 더할 것 두 가지 이상 ② 가장 먼저 할 것과 그 이유
  - 답:① 오류 종류, 요청한 파일 경로, 현재 작업 폴더, 발생 시각을 로그에 남기고 운영자에게 즉시 알리는 기능 ② 현재 빈 설정을 사용 중인지 보여 주는 상태 확인 기능 ③ 검증된 정상 설정 백업으로 복구하고 다시 읽는 기능을 추가하겠다. 가장 먼저 로그와 알림 기능을 추가하겠다. (가)에서는 정상이어야 할 users.json과 일부러 깨뜨린 users_broken.json까지 모두 「설정 파일 없음」으로 나왔으므로, JSON 문법 오류로 단정하지 않고 실행 위치와 파일 경로부터 확인해야 한다. 오류 경로와 작업 폴더를 즉시 알면 원인을 빨리 찾아 복구할 수 있다. 복구 후에는 정상 파일에서 사용자 6명을 읽고, 없는 파일과 깨진 파일에서 각각 알맞은 경고와 빈 설정을 반환하는지 확인하겠다.

### 문제 6-1 · 꼭 지켜야 할 네 가지를 테스트로 설계하고, 팀원의 제안을 시험하기

- (가) `test_policy_extra.py` 를 실행한 출력 전체를 붙여 넣고, 실패한 줄 번호와 `AssertionError:` 뒤에 나온 글자를 적어 주세요.
  - 쓸 내용: ① `test_policy_extra.py` 출력 전체 ② 실패한 줄 번호 ③ `AssertionError:` 뒤의 글자
  - 답: 5번은 통과했고, 6번은 14번째 줄에서 실패했다. 오류 설명은 `6. 만료 정각에도 허용되어야 한다(팀원 제안)`이다.

```
5 통과
Traceback (most recent call last):
  File "C:\Users\User\Desktop\security-agent-toolkit\access_control\test_policy_extra.py", line 14, in <module>
    assert ok == True, "6. 만료 정각에도 허용되어야 한다(팀원 제안)"
           ^^^^^^^^^^
AssertionError: 6. 만료 정각에도 허용되어야 한다(팀원 제안)
```

- (나) 🔍 그 실패는 코드가 틀렸다는 뜻인가요, 제안이 우리가 정한 만료 규칙과 다르다는 뜻인가요? 근거를 적어 주세요.
  - 쓸 내용: ① 코드가 틀렸는지, 제안이 정책과 다른지 ② 우리가 정한 만료 규칙과 3번 테스트 결과를 근거로 한 이유
  - 답: 팀원의 제안이 기존 정책과 다르기 때문이다. 예외는 `now < expires`일 때만 유효하다. 3번 테스트도 17:59 허용, 18:00 거부로 통과했으므로 만료 정각의 허용을 기대하는 제안이 실패하는 것이 정상이다.

- (다) 🔍 정책 코드를 바꿀 때마다 `test_policy.py` 의 1 ~ 4번 테스트를 돌리지 않으면 어떤 사고가 날 수 있나요? 네 개 중 하나를 골라, 그 테스트가 막아 주는 사고를 구체적인 장면으로 적어 주세요.
  - 쓸 내용: ① 고른 테스트 ② 그 테스트가 막아 주는 사고 장면
  - 답: 3번 테스트를 골랐다. `<`를 실수로 `<=`로 바꾸면 만료 시각인 18:00에도 seoyeon이 정산 자료를 조회할 수 있다. 3번 테스트는 만료 정각의 거부를 확인해 이 사고를 막는다.
