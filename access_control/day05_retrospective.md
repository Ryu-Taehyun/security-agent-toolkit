# 3과목 총정리 (이름 · 2026-11-02(월))

## 상황 1 · 새 직원이 들어옴 (본보기)
- 원인: 데이터 문제입니다. hana 가 입사했는데 `users.json` 에 hana 가 아직 없습니다. 시스템은 사용자 파일에 없는 사람의 요청을 모두 「등록되지 않은 사용자」로 거부합니다.
- 고칠 파일: `config/users.json`
- 어떻게 고치나요: 새로 넣습니다. hana 를 `"hana": {"role": "sales", "employed": true}` 로 `users.json` 에 적습니다. `role` 은 hana 가 맡을 일에 맞는 역할로 정합니다.
- 고친 뒤 확인: hana 의 요청을 다시 판정해서 「등록되지 않은 사용자」가 사라지는지 봅니다.

## 상황 2 · 퇴사자 계정으로 요청이 계속 들어옴 (본보기)
- 원인: 데이터가 정리되지 않았습니다. dami 는 퇴사했는데 dami 의 항목이 `users.json` 에 그대로 남아 있어서 같은 시도가 계속 들어옵니다. `employed` 가 `false` 이면 요청은 거부되지만, 남은 항목 때문에 퇴사자 계정 점검에는 계속 걸립니다.
- 고칠 파일: `config/users.json`
- 어떻게 고치나요: dami 의 `"employed"` 가 `true` 로 남아 있다면 먼저 `false` 로 바꿉니다. 이미 `false` 이면 그대로 두고, dami 의 항목 전체를 `users.json` 에서 지웁니다.
- 고친 뒤 확인: 같은 요청이 「등록되지 않은 사용자」로 거부되고, 퇴사자 계정 점검이 통과로 바뀌는지 봅니다.
- 더 써 보고 싶은 것(선택): `check_permission` 이 퇴사 여부를 역할 확인보다 먼저 보는 이유는 무엇일까요?

## 상황 3 · 다른 팀 업무를 잠시 지원함
- 원인: 기존 역할에 다른 팀 업무 권한이 없습니다.
- 고칠 파일: `config/exceptions.json`
- 어떻게 고치나요: 필요한 권한만 사용자·만료 시각·사유와 함께 예외로 추가합니다.
- 고친 뒤 확인: 만료 전에는 허용되고, 만료 시각부터 거부되는지 봅니다.
- 더 써 보고 싶은 것(선택): 임시 지원은 역할 변경보다 기한 있는 예외가 알맞습니다.

## 상황 4 · 새 권한이 필요함
- 원인: 해당 역할에 업무상 필요한 권한이 없습니다.
- 고칠 파일: `config/roles.json`
- 어떻게 고치나요: 요청을 검토·승인한 뒤 해당 역할에 필요한 권한만 추가합니다.
- 고친 뒤 확인: 대상 역할은 허용되고, 다른 역할에는 권한이 생기지 않았는지 봅니다.
- 더 써 보고 싶은 것(선택): 같은 역할의 사용자 모두에게 영향을 주므로 먼저 확인합니다.

## 상황 5 · 안 쓰는 권한이 쌓임
- 원인: 장기 미사용 권한과 만료 예외가 정리되지 않았습니다.
- 고칠 파일: `config/roles.json`, `config/exceptions.json`
- 어떻게 고치나요: `review_unused.py`로 후보를 찾고, 업무 필요성을 확인해 불필요한 권한·예외를 삭제합니다.
- 고친 뒤 확인: 점검을 다시 실행해 대상이 줄고, 필요한 업무는 계속 허용되는지 봅니다.
- 더 써 보고 싶은 것(선택): 사용 이력이 없다고 무조건 회수하지 않습니다.

## 상황 6 · 민감한 권한을 회수해야 함
- 원인: 쓰기 등 민감한 권한이 불필요하게 남아 있습니다.
- 고칠 파일: 부여 경로에 따라 `config/roles.json` 또는 `config/exceptions.json`
- 어떻게 고치나요: 영향 범위를 확인해 회수 계획을 세우고, 승인된 건만 실행한 뒤 `revocation_log.json`에 기록합니다.
- 고친 뒤 확인: 회수한 권한은 거부되고, 승인 대기 건은 실행되지 않았는지 봅니다.
- 더 써 보고 싶은 것(선택): 이력에 회수 사유도 남겨야 나중에 설명할 수 있습니다.

## 상황 7 · 새벽 외부 접속, 그리고 정상 직원이 계속 거부됨
- 원인: 새벽 외부 요청은 조건 위반입니다. 정상 직원의 반복 거부는 `is_work_time`이 비어 있어 `None`을 반환하기 때문입니다.
- 고칠 파일: `conditional.py` (정책 기준은 `config/conditions.json`)
- 어떻게 고치나요: 시간 판정을 `start <= now.hour < end`로 구현하고, 접속 위치 변수명을 `allowed_networks`로 맞춥니다.
- 고친 뒤 확인: `SALES:CHANGE`는 사무실 09시에 허용, 18시와 새벽 02시 외부 접속에는 거부되는지 봅니다.
- 더 써 보고 싶은 것(선택): 로그인 때뿐 아니라 요청마다 시간·접속 위치를 확인해야 합니다.

## 상황 8 · 매주 어긋남을 확인해야 함
- 원인: 퇴사·예외 만료·부서 이동으로 계정과 권한 상태가 달라집니다.
- 고칠 파일: `config/week_state.json`, `checklist.py`, `weekly_report.py`
- 어떻게 고치나요: 최신 상태로 퇴사자·만료 예외·부서와 역할 불일치를 점검하고 주간 보고서를 남깁니다.
- 고친 뒤 확인: 보고서의 문제 목록이 실제 데이터와 맞고, 조치 후 재점검에서 사라지는지 봅니다.
- 더 써 보고 싶은 것(선택): 거부율과 반복 거부 사용자도 함께 확인합니다.
