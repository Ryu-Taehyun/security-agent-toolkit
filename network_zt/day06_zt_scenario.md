# A사 Zero Trust 적용 방안

## 5대 원칙 적용 방안

- ID: 모든 직원 로그인 경로에 MFA를 적용한다.
- Device: 본인 등록 기기인지 확인하고 백신·패치 상태를 점검한다.
- Network: 서버 구역과 직원 PC 구역을 나누고, 필요한 포트만 연다.
- Application: 부서별로 맡은 자원만 허용하고 관리자 기능은 별도 권한을 확인한다.
- Policy: 시간·국가·기기 상태·MFA·조회량으로 위험도를 판단하고, 반복 조회의 누적 건수도 확인한다.

## 판단과 집행

- PDP(결정): 포털의 정책 서버에서 재직·등록 기기·자원 권한을 확인하고 위험 점수로 결정한다.
- PEP(집행): 포털 앞 프록시에서 PDP의 결정에 따라 통과·추가확인·차단을 집행한다.

## 흐름도

```
사용자 --요청--> PEP --요청 정보--> PDP
                                  |
                 필수 조건: 재직·등록 기기·자원 권한
                 권한 변경: account_admin 역할도 확인
                                  |
                 실패: 거부 / 통과: 위험 점수 계산
                 정산 조회: 50점 이상 거부, 20점 이상 추가확인
                 권한 변경: 50점 이상 거부, 10점 이상 추가확인
                 나머지: 허용
                                  |
PEP <--------- 결정 --------------+
 |-- 허용 -----> 해당 자원으로 통과
 |-- 추가확인 -> MFA 등 추가 검증 후 PDP 재판정
 +-- 거부 -----> 차단하고 로그 기록
```

## 최소권한 기준 (목록에 없으면 거부)

- 재무팀: SETTLE(정산 내역) 조회만 허용한다.
- 영업팀: SALES(영업 실적) 조회만 허용한다.
- 서비스 계정 batch-night: SRV-BATCH에서 매일 02:00 정산 집계에 필요한 SETTLE 조회만 허용한다.
- 위 목록에 없는 자원·동작은 기본 거부한다.

## 스코어링 결과

- 항목별 점수: MFA 10 / 기기 5 / 최소권한 15 / 세그멘테이션 0 / 위험기반인증 0
- 총점: 30 / 100 (교재의 직원 12명 기준)
- 먼저 올릴 항목과 이유: MFA 적용률. 비밀번호 유출로 해외 로그인이 성공한 사례가 있으므로, 모든 직원 로그인 경로에 MFA를 우선 적용한다.
